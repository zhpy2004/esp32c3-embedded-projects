# ESP32-C3 电子宠物 — 项目架构说明

## 架构总览

整个项目分为 **三层**：驱动层 → 应用层 → 主程序，所有文件通过 `game_config.h` 共享配置。

```
┌─────────────────────────────────────────────────┐
│              pet_game.ino (主程序)                │
│   setup() 初始化  /  loop() 状态机调度             │
├─────────┬──────────┬──────────┬────────┬─────────┤
│pet_core │ pet_save │pet_sensor│ pet_ui │ pet_web │
│宠物逻辑  │ 存档管理  │ 传感器管理 │ OLED渲染│ Web作弊 │
├─────────┴──────────┴──────────┴────────┴─────────┤
│                    驱动层                         │
│ oled_ssd1315 │ epd_ssd1680 │ ds1307 │ ttp229     │
│ buzzer       │ bh1750      │ dht11  │ mpu6050    │
│ wifi_ntp     │                                   │
├──────────────────────────────────────────────────┤
│              game_config.h (全局参数)              │
└──────────────────────────────────────────────────┘
```

## 各文件职责与协作关系

### 1. `game_config.h` — 全局配置中心

所有数值常量集中在这一个文件：引脚分配、I2C 地址、属性范围、衰减速率、食物价格/回复量、战斗参数、采样周期、键盘映射等。其他所有文件都 `#include "game_config.h"`，改参数只改这一个地方。

### 2. 驱动层（9 个 .h/.cpp）

每个驱动只负责一个硬件芯片，提供 `xxx_init()` + 功能函数，对上层屏蔽寄存器细节：

| 驱动 | 硬件 | 提供的能力 |
|---|---|---|
| `oled_ssd1315` | OLED 显示屏 | 画点/线/文字/位图/刷新 |
| `epd_ssd1680` | 墨水屏 | 黑白+红色双色图像显示 |
| `ds1307` | RTC 时钟 | 读/写当前时间 |
| `ttp229` | 触摸键盘 | 读取 16 键按键状态 |
| `buzzer` | 蜂鸣器 | 播放频率/时长、开/关 |
| `bh1750` | 光照传感器 | 读取环境光照度 (lux) |
| `dht11` | 温湿度传感器 | 读取温度/湿度 |
| `mpu6050` | 加速度计 | 读取三轴加速度 (检测摇晃) |
| `wifi_ntp` | WiFi + NTP | 连接网络、NTP 校时 |

### 3. 应用层 — 五大模块

#### `pet_core`（宠物核心逻辑）

- 管理宠物的**运行时数据**：`pet_status_t`（alive/hp/mood/coins/appearance）和 `env_data_t`（温度/光照/是否夜间）
- 提供所有**游戏玩法** API：喂食 `pet_feed()`、互动 `pet_interact_pet()/shake()`、小游戏 `pet_minigame_*()`、打工 `pet_work_*()`、战斗 `pet_fight_*()`
- 负责**自然衰减** `pet_decay_tick()`：每分钟扣 HP/Mood，夜间减半
- 负责**外观计算** `pet_update_appearance()`：根据 HP/Mood/存活状态决定表情（Happy/Normal/Hungry/Sad/Sleep/Dead）
- 提供**作弊接口**：`pet_cheat_set_hp()` 等，供 Web 模块调用
- **不依赖任何驱动**，只做纯逻辑计算

#### `pet_sensor`（传感器管理）

- **向下调用**驱动层：ttp229（键盘）、mpu6050（摇晃）、bh1750（光照）、dht11（温湿度）
- **向上提供**统一的 `sensor_poll()` 接口，返回事件位掩码
- 内部用**时间片轮询**：键盘 50ms、加速度 200ms、光照/温湿度 5s、衰减 60s、自动存档 90s
- 采样后自动更新 `pet_core` 里的 `env_data_t`（光照 → 夜间判断、温度 → 异常标记）
- 主循环只需调用一次 `sensor_poll()`，就能拿到所有事件

#### `pet_save`（存档管理）

- **向下调用** ESP32 NVS（`Preferences` 库，Flash 内置键值存储）和 `ds1307`（读取时间戳）
- **向上调用** `pet_core` 的 `pet_restore()` / `pet_get_status()` 来恢复/获取宠物状态
- **A/B 双槽交替写入**：`slot_a` / `slot_b` 两个 NVS 键交替写入，防止掉电损坏
- **XOR 校验**：前 19 字节异或得到 checksum，读取时校验
- **离线衰减恢复**：加载存档时，用当前 RTC 时间 - 存档时间 = 离线分钟数，调用 `pet_offline_decay()` 模拟衰减

#### `pet_ui`（OLED UI 渲染）

- **向下调用** `oled_ssd1315` 的绘图 API
- **向上读取** `pet_core` 的状态（HP/Mood/Coins/State）来决定画什么
- 通过 `ui_extra_t` 结构体与主程序共享附加状态（菜单光标、战斗结果、打工进度等）
- 根据当前 `game_state_t`（13 个状态）绘制不同画面：主界面、喂食菜单、战斗动画、结果页等
- Toast 系统：临时消息浮层，不打断当前状态

#### `pet_web`（Web 作弊控制台）

- **向下调用** WiFi 连接和 `pet_core` 的作弊接口
- 启动 HTTP Server（端口 80），手机浏览器访问即可修改宠物属性
- `web_run()` 在 loop 中处理 HTTP 请求，解析 GET 参数调用 `pet_cheat_*()` 函数
- 也提供 `web_ntp_sync()` 复用 WiFi 做 NTP 校时

#### `pet_images.h`（宠物位图）

- 存放 6 种表情的墨水屏位图数据（黑白层 + 红色层）
- 由 `convert.py` 脚本从图片自动生成
- 主程序通过 `PET_IMG_BW[appearance]` / `PET_IMG_RED[appearance]` 索引取用

## 主程序 `pet_game.ino` 运行流程

### `setup()` 启动顺序

```
I2C 总线 → OLED(显示Loading) → RTC → 存档加载(恢复宠物/离线衰减)
→ 蜂鸣器 → 传感器 → 墨水屏(初始外观) → WiFi+Web → 进入 STATE_MAIN
```

### `loop()` 每帧执行

```
1. sensor_poll()          → 拿到事件位掩码 (按键/摇晃/衰减/存档)
2. 按键音阶反馈            → 非阻塞蜂鸣器 50ms
3. 按键分发                → 根据当前状态分发到不同处理函数
4. handle_events()        → 处理摇晃互动、衰减、自动存档
5. update_timed_states()  → 打工结算、战斗结算、动画超时
6. ui_draw()              → 每 500ms 刷新 OLED
7. web_run()              → 处理 HTTP 请求
8. refresh_epd_if_needed()→ 外观变化时刷新墨水屏
```

### 状态机（13 个状态）

| 状态 | 含义 | 触发方式 |
|---|---|---|
| `STATE_INIT` | 初始化中 | 上电 |
| `STATE_MAIN` | 主界面 | 默认状态 |
| `STATE_FEED_MENU` | 喂食菜单 | 按键 KEY_FEED |
| `STATE_FEEDING` | 喂食动画 | 选择食物后 |
| `STATE_PLAY_MENU` | 互动菜单 | 按键 KEY_PLAY |
| `STATE_PLAYING` | 互动动画 | 抚摸/摇晃后 |
| `STATE_MINIGAME` | 逗乐小游戏 | 菜单确认 |
| `STATE_MINIGAME_RESULT` | 小游戏结果 | 输入完成/超时 |
| `STATE_WORKING` | 打工中 | 按键 KEY_WORK |
| `STATE_FIGHTING` | 战斗中 | 按键 KEY_FIGHT |
| `STATE_FIGHT_RESULT` | 战斗结果 | 2s 后自动结算 |
| `STATE_DEAD` | 死亡 | HP ≤ 0 |
| `STATE_NTP_SYNC` | NTP 校时 | 按键 KEY_NTP |

## 数据流向总结

```
传感器硬件 → pet_sensor → pet_core(env_data)
                              ↕
按键 → pet_game.ino 状态机 → pet_core(status) → pet_ui → OLED
                              ↕                        → epd → 墨水屏
                         pet_save ↔ NVS (Flash)
                              ↕
手机浏览器 → pet_web → pet_core(cheat)
```

**pet_core 是数据中心**，所有模块都围绕它工作：

- `pet_sensor` 往里写环境数据
- 主程序调它的玩法 API
- `pet_ui` 从里读状态来绘图
- `pet_save` 负责持久化到 NVS (Flash)
- `pet_web` 通过作弊接口直接改数据
