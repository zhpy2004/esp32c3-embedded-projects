# ESP32-C3 电子宠物 - 方案设计文档

## 一、项目概述

基于 ESP32-C3 开发板，设计一款桌面电子宠物系统。宠物状态通过电子墨水屏（外观图像）和 OLED（文字/数值）双屏显示，用户通过 TTP229 触摸键盘进行交互，多种传感器为游戏增加环境感知维度，Wi-Fi + Blinker APP 提供手机端"作弊"功能。

---

## 二、硬件清单与总线分配

### 2.1 硬件清单

| 序号 | 模块 | 型号/规格 | 接口 | I2C地址 |
|------|------|-----------|------|---------|
| 1 | 主控 | ESP32-C3 | - | - |
| 2 | 触摸键盘 | TTP229-LSF 16键 | I2C | 0x57 |
| 3 | 温湿度传感器 | DHT11 | 单总线 | - |
| 4 | 光强传感器 | BH1750FVI | I2C | 0x23 |
| 5 | 电子墨水屏 | 2.13" BWR (SSD1680) | SPI | - |
| 6 | 姿态传感器 | MPU-6050 | I2C | 0x69 (AD0=HIGH) |
| 7 | 人体热释电传感器 | PIR | GPIO | - |
| 8 | OLED 显示屏 | SSD1315 128x64 | I2C | 0x3C |
| 9 | 实时时钟 | DS1307 | I2C | 0x68 |
| 10 | EEPROM | AT24C32D | I2C | 0x50 |

> **注意：** MPU-6050 默认地址 0x68 与 DS1307 冲突，需将 MPU-6050 的 AD0 引脚接高电平，地址变为 0x69。

### 2.2 引脚分配

| GPIO | 功能 | 说明 |
|------|------|------|
| 0 | 蜂鸣器 (PWM) | LEDC 驱动无源蜂鸣器 |
| 1 | DHT11 DATA | 单总线温湿度 |
| 2 | EPD_BUSY | 墨水屏忙信号 (输入) |
| 3 | EPD_RST | 墨水屏复位 |
| 4 | EPD_SCK | 软件 SPI 时钟 |
| 5 | EPD_MOSI | 软件 SPI 数据 |
| 6 | EPD_CS | 墨水屏片选 |
| 7 | EPD_DC | 墨水屏数据/命令 |
| 8 | I2C SDA | 共享总线 (6个从设备) |
| 9 | I2C SCL | 共享总线 |
| 10 | PIR_OUT | 人体热释电 (数字输入) |

### 2.3 I2C 总线拓扑

```
I2C Bus (SDA=GPIO8, SCL=GPIO9, 100kHz)
  ├── 0x3C  OLED SSD1315
  ├── 0x23  BH1750FVI 光强传感器
  ├── 0x50  AT24C32D EEPROM
  ├── 0x57  TTP229-LSF 触摸键盘
  ├── 0x68  DS1307 RTC
  └── 0x69  MPU-6050 姿态传感器 (AD0=HIGH)
```

> I2C 频率设为 100kHz（DS1307 最大支持 100kHz），总线上 6 个设备地址无冲突。

## 三、宠物角色设计

### 3.1 属性定义

| 属性 | 范围 | 显示方式 | 说明 |
|------|------|----------|------|
| 外观 | 6 种状态图 | 墨水屏 | 开心/普通/饥饿/低落/睡觉/死亡 |
| 体力值 (HP) | 0 ~ 100 | OLED 进度条 | 归零则宠物死亡 |
| 心情值 (Mood) | 0 ~ 100 | OLED 进度条 | 影响打工收益 |
| 金币 (Coin) | 0 ~ 99999 | OLED 数字 | 用于购买食物 |

### 3.2 外观状态与切换条件

```
                  ┌──────────────────────────────────────┐
                  │          外观显示 (墨水屏)            │
                  └──────────────────────────────────────┘

     HP>70 且 Mood>70        HP>30 且 Mood>30        HP≤30 或 Mood≤30
     ┌──────────┐           ┌──────────┐           ┌──────────┐
     │  开心 :D  │           │  普通 :|  │           │  低落 :(  │
     └──────────┘           └──────────┘           └──────────┘

          HP≤30                                       HP=0
     ┌──────────┐                                ┌──────────┐
     │  饥饿 >< │                                │  死亡 X_X │
     └──────────┘                                └──────────┘

         夜间(光照<10lux) 且 HP>0
     ┌──────────┐
     │  睡觉 -.- │
     └──────────┘
```

每种外观对应一幅预制的位图，存储在 Flash (PROGMEM) 中。墨水屏仅在外观状态变更时刷新（避免频繁刷新导致的长等待）。

### 3.3 属性自然衰减

| 属性 | 衰减速率 | 白天 (光照>10lux) | 夜间 (光照≤10lux) |
|------|----------|-------------------|-------------------|
| 体力值 | 基础 -1/min | 正常衰减 | 衰减减半 (-1/2min) |
| 心情值 | 基础 -1/2min | 正常衰减 | 衰减减半 (-1/4min) |

**环境因素修正：**
- 温度异常 (>35°C 或 <10°C)：心情额外 -1/min
- 主人在场 (PIR 检测到人)：心情衰减暂停

## 四、活动模式设计

### 4.1 活动总览

| 活动 | 主要效果 | 附带效果 | 触发方式 |
|------|----------|----------|----------|
| 喂食 | HP +20~40 | Coin -5~20 | 键盘选择食物 |
| 互动 | Mood +15~35 | HP -5 | 键盘/传感器 |
| 打工 | Coin +15~40 | HP -15, Mood -10 | 键盘触发 |
| 战斗 | Coin +20~60 | HP -10~30 (随机) | 键盘触发 |

### 4.2 喂食系统

通过键盘选择食物，不同食物效果不同：

| 食物 | 价格 (Coin) | HP 恢复 | Mood 变化 | 说明 |
|------|-------------|---------|-----------|------|
| 面包 | 5 | +20 | +0 | 基础食物 |
| 牛排 | 15 | +40 | +5 | 高级食物 |
| 蛋糕 | 10 | +10 | +15 | 甜食提升心情 |
| 药水 | 20 | +60 | -10 | 大量回血但不好喝 |

**规则：**
- 金币不足时无法购买，OLED 提示 "Not enough coins!"
- 体力已满 (100) 时喂食浪费，OLED 提示 "HP is full!"
- 喂食后墨水屏刷新动画（显示进食外观 1 秒后恢复）

### 4.3 互动系统

多种互动方式，利用不同传感器：

| 互动方式 | 传感器 | 效果 | 冷却时间 |
|----------|--------|------|----------|
| 抚摸 | TTP229 特定键 (连续按) | Mood +15, HP -3 | 30s |
| 摇晃 | MPU6050 加速度突变 | Mood +20, HP -5 | 60s |
| 陪伴 | PIR 持续检测到人 (>5min) | Mood +10 | 5min |
| 逗乐 | 键盘输入特定序列 | Mood +35, HP -5 | 2min |

**逗乐小游戏：** OLED 屏幕随机显示一个 4 位数字序列（如 "3 1 4 2"），玩家用键盘在 10 秒内按顺序输入正确则成功，Mood +35；失败则 Mood +5（安慰奖）。

### 4.4 打工系统

宠物出去打工赚取金币：

- 按键触发后进入打工状态
- 打工持续 30 秒（OLED 显示倒计时进度条）
- 期间不可进行其他活动
- 结算：基础收入 20 Coin
  - 心情 >70：收入 ×1.5（心情好干活卖力）
  - 心情 <30：收入 ×0.5（心情差磨洋工）
- 体力消耗 -15，心情消耗 -10

### 4.5 战斗系统

宠物参与战斗，高风险高回报：

- 按键触发，OLED 显示战斗动画
- 战斗结果基于随机数 + 体力值：
  - **胜利** (概率 = 40% + HP/200)：Coin +40~60, HP -10
  - **失败** (其余概率)：Coin +10, HP -30
  - **大胜** (额外 10% 概率，需 HP>50)：Coin +100, HP -5, Mood +20
- 体力 <20 时禁止战斗，提示 "Too weak to fight!"

## 五、存档系统设计

### 5.1 EEPROM 存储布局

AT24C32D 总容量 4096 字节，分区如下：

| 地址范围 | 大小 | 用途 |
|----------|------|------|
| 0x000 ~ 0x01F | 32B (1页) | 存档槽 A (主存档) |
| 0x020 ~ 0x03F | 32B (1页) | 存档槽 B (备份存档) |
| 0x040 ~ 0x05F | 32B | 系统配置 (保留) |
| 0x060 ~ 0xFFF | 剩余 | 未使用 |

采用 **A/B 双槽交替写入** 策略，防止写入中途断电导致数据损坏。

### 5.2 存档数据结构

```c
typedef struct {
    uint8_t  magic;         // 0xA5 = 有效标记
    uint8_t  version;       // 存档格式版本 (当前=1)
    uint8_t  slot_seq;      // 递增序号，用于判断哪个槽更新
    uint8_t  alive;         // 1=存活, 0=死亡
    uint16_t hp;            // 体力值 (0~100, 用 uint16 留余量)
    uint16_t mood;          // 心情值 (0~100)
    uint32_t coins;         // 金币数
    uint8_t  appearance;    // 当前外观索引
    // --- 存档时间戳 (来自 DS1307) ---
    uint8_t  year;          // 0~99
    uint8_t  month;         // 1~12
    uint8_t  date;          // 1~31
    uint8_t  hour;          // 0~23
    uint8_t  min;           // 0~59
    uint8_t  sec;           // 0~59
    // --- 校验 ---
    uint8_t  checksum;      // 前面所有字节的 XOR
} pet_save_t;               // 共 20 字节，单页可写入
```

### 5.3 存档策略

| 类型 | 触发条件 | 说明 |
|------|----------|------|
| 自动存档 | 每 90 秒 | 定时器触发，写入序号较旧的槽 |
| 手动存档 | 键盘按 "F" 键 | 立即保存，OLED 提示 "Saved!" |
| 活动后存档 | 喂食/打工/战斗结束 | 属性发生较大变化时保存 |

### 5.4 上电恢复逻辑

```
上电 → 读取 DS1307 当前时间
     → 读取存档 A 和 B
     → 校验 magic + checksum
     → 选择 slot_seq 更大的有效存档
     → 计算 Δt = 当前时间 - 存档时间
     → 按衰减速率扣减 HP 和 Mood
        HP = max(0, saved_HP - Δt_minutes × 衰减率)
        Mood = max(0, saved_Mood - Δt_minutes / 2 × 衰减率)
     → HP=0 则标记死亡
     → 恢复完成，进入主界面
```

**离线时间上限处理：** 若 Δt > 24 小时，按 24 小时计算（防止长时间不开机直接暴毙）。

## 六、双屏显示方案

### 6.1 OLED 显示屏 (128x64, SSD1315) — 主交互屏

OLED 作为主界面，分页显示：

```
┌─────────────────────────────┐
│ Page 0: 标题/状态栏          │  "PET  Lv.1  12:30"
│ Page 1: ───────────────────  │  分隔线
│ Page 2: HP [████████░░] 75%  │  体力进度条
│ Page 3: MD [██████░░░░] 55%  │  心情进度条
│ Page 4: Coin: 1250           │  金币数
│ Page 5: T:25°C H:60% L:320  │  环境传感器
│ Page 6: ───────────────────  │  分隔线
│ Page 7: 0:Feed 1:Play 2:Work │  操作提示
└─────────────────────────────┘
```

刷新频率：500ms 一次。

### 6.2 电子墨水屏 (2.13" BWR, SSD1680) — 宠物外观屏

- 分辨率：122 × 250 (黑/白/红三色)
- 用途：显示宠物外观图像
- 刷新策略：仅在外观状态变更时全刷（约 15 秒）
- 6 种预制位图（开心/普通/饥饿/低落/睡觉/死亡）
- 黑色画宠物轮廓和身体，红色画腮红/爱心/警告标记
- 位图使用 PCtoLCD2002 取模，存储在 PROGMEM 中

## 七、触摸键盘功能映射

TTP229 16 键布局与功能：

```
     ┌─────┬─────┬─────┬─────┐
     │  0  │  1  │  2  │  3  │
     │Feed │Play │Work │Fight│
     ├─────┼─────┼─────┼─────┤
     │  4  │  5  │  6  │  7  │
     │ ↑   │ ↓   │ OK  │Back │
     ├─────┼─────┼─────┼─────┤
     │  8  │  9  │  A  │  B  │
     │     │     │     │     │
     ├─────┼─────┼─────┼─────┤
     │  C  │  D  │  E  │  F  │
     │Pet  │Pet  │NTP  │Save │
     │Touch│Touch│Sync │     │
     └─────┴─────┴─────┴─────┘
```

**主界面功能：**
- **0 (Feed)：** 进入喂食菜单
- **1 (Play)：** 进入互动菜单
- **2 (Work)：** 开始打工
- **3 (Fight)：** 开始战斗
- **4/5 (↑/↓)：** 菜单导航
- **6 (OK)：** 确认选择
- **7 (Back)：** 返回上级
- **8-9：** 逗乐小游戏数字输入
- **A-B：** 逗乐小游戏数字输入
- **C/D (Pet Touch)：** 抚摸宠物（连按提升心情）
- **E (NTP)：** Wi-Fi NTP 校时
- **F (Save)：** 手动存档

## 八、传感器集成方案

### 8.1 温湿度传感器 (DHT11)

| 参数 | 说明 |
|------|------|
| 引脚 | GPIO1, 单总线协议 |
| 采样周期 | 每 30 秒读取一次 |
| 游戏影响 | 温度 >35°C 或 <10°C 时，心情额外衰减 |
| 显示 | OLED 第 5 行显示 "T:xx°C H:xx%" |

### 8.2 光强传感器 (BH1750FVI)

| 参数 | 说明 |
|------|------|
| 地址 | 0x23 (ADDR=LOW) |
| 采样周期 | 每 10 秒读取一次 |
| 游戏影响 | <10 lux 判定为夜间，宠物进入睡眠状态，衰减减半 |
| 显示 | OLED 第 5 行显示 "L:xxx lx" |

### 8.3 姿态传感器 (MPU-6050)

| 参数 | 说明 |
|------|------|
| 地址 | 0x69 (AD0=HIGH，避免与 DS1307 冲突) |
| 采样周期 | 每 200ms 读取加速度 |
| 游戏影响 | 检测到摇晃动作（加速度突变 > 阈值）触发 "摇晃互动" |
| 检测算法 | \|ΔAccel\| > 2g 判定为摇晃事件 |

### 8.4 人体热释电传感器 (PIR)

| 参数 | 说明 |
|------|------|
| 引脚 | GPIO10, 数字输入 |
| 采样周期 | 每 1 秒读取 |
| 游戏影响 | 检测到人体存在时，心情衰减暂停；持续 5 分钟以上额外 Mood +10 |
| 状态指示 | OLED 状态栏显示人体存在图标 |

- ESP32-C3 通过 Wi-Fi 连接到路由器

### 10.2 主循环架构

```c
void setup() {
    // 1. 串口初始化
    // 2. I2C 总线初始化 (SDA=8, SCL=9, 100kHz)
    // 3. 各驱动初始化 (OLED → DS1307 → AT24C32D → TTP229 → ...)
    // 4. 加载存档 → 计算离线衰减 → 恢复宠物状态
    // 5. 墨水屏绘制初始外观
    // 6. Wi-Fi + Blinker 初始化
    // 7. OLED 显示主界面
}

void loop() {
    // === 时间片轮询架构 (非阻塞) ===

    // [每次循环] 触摸键盘轮询 + 按键处理
    ttp229_poll() → handle_key()

    // [每 200ms] MPU6050 读取 + 摇晃检测
    mpu6050_check_shake()

    // [每 500ms] OLED 界面刷新
    oled_refresh()

    // [每 1s] PIR 读取 + 属性衰减计算
    pir_read() + pet_decay_tick()

    // [每 10s] BH1750 光照读取
    bh1750_read()

    // [每 30s] DHT11 温湿度读取
    dht11_read()

    // [每 90s] 自动存档
    auto_save()

    // [持续] Blinker 事件处理
    blinker_run()

    // [按需] 墨水屏刷新 (外观状态变更时)
    epd_refresh_if_needed()
}
```

## 十一、关键流程

### 11.1 上电启动流程

```
上电
 ├─ Serial.begin(115200)
 ├─ Wire.begin(8, 9)                 // I2C 初始化
 ├─ oled_init() → 显示启动画面 "Loading..."
 ├─ ds1307_init() → 读取当前时间
 ├─ at24c32d 存档加载:
 │   ├─ 读取 Slot A 和 Slot B
 │   ├─ 校验 magic + checksum
 │   ├─ 取 slot_seq 更大的有效存档
 │   ├─ 计算 Δt = now - save_time
 │   ├─ Δt > 24h ? 按 24h 计算 : 正常
 │   ├─ HP -= Δt_min × 1 (衰减)
 │   ├─ Mood -= Δt_min / 2 (衰减)
 │   ├─ HP < 0 ? HP = 0, alive = false
 │   └─ 恢复完成
 ├─ epd_init() → 绘制宠物外观
 ├─ bh1750_init()
 ├─ mpu6050_init()
 ├─ pir_init()
 ├─ ttp229_init()
 ├─ buzzer 开机提示音
 ├─ Blinker.begin() (后台 Wi-Fi 连接)
 └─ 进入 STATE_MAIN
```

### 11.2 自动存档流程

```
定时器 (90s) 触发
 ├─ ds1307_read_time() 获取当前时间
 ├─ 填充 pet_save_t 结构体
 ├─ 计算 checksum (XOR)
 ├─ 判断当前活跃槽 (A 或 B)
 ├─ 写入非活跃槽 (A/B 交替)
 ├─ at24c32d_write_page() 单页写入 (20 字节 < 32 字节/页)
 ├─ ACK Polling 等待写入完成
 └─ Serial.println("[SAVE] Auto-saved")
```

### 11.3 战斗流程

```
按键 3 (Fight) 触发
 ├─ 检查 HP >= 20，否则提示 "Too weak!"
 ├─ 进入 STATE_FIGHTING
 ├─ OLED 显示战斗动画 (2s)
 │   ├─ 第 1 帧: "VS Monster!"
 │   ├─ 第 2 帧: "Fighting..."
 │   └─ 蜂鸣器播放战斗音效
 ├─ 计算结果:
 │   ├─ win_rate = 40 + HP / 2 (%)
 │   ├─ rand(0, 100) < win_rate?
 │   │   ├─ 胜利: Coin += 40~60, HP -= 10
 │   │   │   └─ 10% 大胜: Coin += 100, HP -= 5, Mood += 20
 │   │   └─ 失败: Coin += 10, HP -= 30
 │   └─ HP = max(0, HP)
 ├─ STATE_FIGHT_RESULT → OLED 显示结果 (3s)
 ├─ 自动存档
 └─ 返回 STATE_MAIN
```

## 十五、风险与注意事项

1. **I2C 总线稳定性：** 6 个设备共享总线，需确保上拉电阻合适 (4.7kΩ)，总线电容不超标。
2. **墨水屏刷新时间：** 全刷约 15 秒，期间不可操作墨水屏。应在后台进行，不阻塞主循环。
3. **EEPROM 写入寿命：** AT24C32D 擦写寿命 100 万次。90 秒存档一次，连续运行约 2.8 年才会达到寿命上限，无需担心。
4. **Blinker 免费版限制：** 每天消息数有上限，5 秒一次推送不会超限。
5. **MPU6050 与 DS1307 地址冲突：** 必须将 MPU6050 的 AD0 接高电平。
6. **ESP32-C3 GPIO 数量：** 刚好 11 个 GPIO 全部用完，无剩余引脚。如需扩展可考虑 I2C GPIO 扩展器 (PCF8574)。
7. **DHT11 时序：** DHT11 单总线协议对时序要求严格，读取期间需关闭中断，可能影响 Blinker 通信。建议 DHT11 读取频率不超过每 30 秒一次。
